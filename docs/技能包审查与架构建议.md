# 技能包审查与架构建议

审查日期：2026-09-26。范围：本地技能、插件清单、源工作流、核心脚本，以及临时目录中的定向运行验证。本文是设计建议；没有修改原始技能包、接入付费服务或实现业务应用。

## 结论

可以去掉付费 MCP 的强制依赖，保留业务技能，以 CrewAI Flow 编排角色。不能把删除 MCP 理解成仅凭提示词就能获得同等法规、类案检索能力。

推荐结构：业务 Skills + CrewAI Flow/Agent/Task + 本地业务工具 + 可替换的数据来源适配器。MCP 是其中一种可选适配器，默认不启用、不阻塞启动。

两个包互补：法检 Pro 提供研究、类案筛选和引用溯源方法；诉法法提供案件整理、证据时间线、诉前评估与文书草拟方法。它们是业务素材和部分工具代码，不是完整后端应用。

## 2. MCP 依赖拆分

### 法检 Pro

- `.codebuddy-plugin/plugin.json` 的 `dependencies.connectors` 明确包含 `pkulaw`。
- `agents/legal-search-pro.md:70` 要求检索前发现并尝试北大法宝，再查华宇元典；不是普通可选提示。
- `skills/legal-search-engine/SKILL.md:153` 起包含完整专业库前置规则和宿主专属工具名。
- `skills/case-retrieval/SKILL.md:20` 重复强制发现/调用要求。
- `skills/legal-verification-workbench/SKILL.md:151` 在补检环节再次要求优先专业库。
- `legal-output-formatter`、专家定义与其他技能要求隐藏连接状态，不能原样作为新产品的来源透明度规则。

需要同时改插件元数据、专家提示词、检索技能、案例技能、补检流程、输出规则；只删除清单中的 `pkulaw` 不够。

本地脚本接收已经取得的 JSON 来源，负责保存、索引、关联和报告生成。它们没有实现北大法宝或华宇元典的远程检索客户端。保留脚本不等于已完成 MCP 接入。

### 诉法法

- 顶层 `plugin.json` 未声明必需 MCP 连接器。
- 源 README 明确 Gmail、定时任务集成为可选项，邮件不可用时输出本地草稿。
- 源工作流还引用法律检索、Drive、Slack、文档审阅平台等能力；可映射为上传材料、案件数据库、本地检索工具和可选远程来源。
- README 所称的 `.mcp.json` 不在当前导出包内，因此当前包不包含完整连接配置。

### 新项目统一契约（建议，尚未实现）

对角色提供 `search_statutes`、`get_statute_text`、`search_cases`、`get_case_text`、`search_case_materials` 等窄接口，不暴露供应商专属工具名。

适配器返回统一结果：

- 调用状态：成功、有结果但不完整、无结果、未配置、不可用、失败。
- 来源信息：供应商、原始 URL/文档标识、获取时间、检索范围。
- 文本信息：完整性、原文、页码/条号、内容哈希。
- 法规信息：法域、发布/施行/失效日期、版本、效力状态及核验依据。

本地材料可以直接使用；公开权威来源作为可实现的检索路径；付费 MCP 仅在配置并启用后参与。公开网站的访问和覆盖能力须实际验证，不能承诺与专业数据库等价。

检索服务不可用不能伪装成“无相关案例”。用户应看到本次覆盖范围及未核验项；技术报错细节留在运行记录中。

## 3. 迁移前发现的问题

### 3.1 法规版本会被合并，且状态选择偏向现行有效

`scripts/lib.mjs:23` 的来源 ID 基于 provider/title/url/lawId，不包含版本。`persist-legal-sources.mjs:83` 的 `preferStatus()` 优先选择“现行有效”，同一来源的文本会合并。

定向验证：输入同 provider/title/url 的两个虚构版本，一条“现行有效”、一条“已废止”，得到 1 个来源、两段相互冲突的第一条，最终状态仍为“现行有效”。

最小修改建议：分开法律文档身份与不可变版本身份；版本中记录生效区间和原文哈希。不同版本不合并正文。状态矛盾进入待复核，适用版本按事实发生时间与法律适用规则确定。

### 3.2 已关联不能当成结论已核实

`match-evidence.mjs:3` 明确说明自身是溯源助手。声明的来源与条号存在即可建立关联；相似度只是候选查找。

定向验证：虚构原文写“禁止乙类操作”，结论写“允许乙类操作”，声明同一条号后统计仍为 `associated=1`；HTML 验收也通过。运行健康状态因来源短文本提示为 `ok=false`，并非所有健康检查都通过。

最小修改建议：分别记录来源关联状态、来源有效性、结论支持程度和人工复核状态。复核角色检查事实与规则是否支持结论；结构校验检查引用是否存在。两者均不能单独作为正确性保证。

### 3.3 生成成功与可交付状态不是一个字段

`run-verification-pipeline.mjs` 的 `all` 路径会先生成 HTML，再返回 health；即使需要补检也可能 `success=true`。单独 `assert-html` 主要检查模板和关联统计，不等于覆盖全部来源完整性与补检门禁。

最小修改建议：后端使用明确的任务状态（草稿、需补充、待复核、可交付、失败）。交付状态由完整校验结果决定，不能仅判断退出码、`success` 或 HTML 是否存在。补检轮数、超时和费用预算有上限，无法补全时保留缺口。

### 3.4 内置法律引用有过时条号

`legal-search-engine/SKILL.md:132` 起的冲突规则表仍引用《立法法》第 87—89、92、94 条。核对 2023 年修正文本：法律效力关系见第 99 条，同一机关制定规则的新旧/特别一般关系见第 103 条，新一般与旧特别冲突处理见第 105 条等。

官方核对来源：[市场监管总局公布的《中华人民共和国立法法》](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/bgt/art/2025/art_4e6af5cd28844e98b847ac2d7c0487a4.html)。这是已发现实例，不代表已完成全部法律规则审定。

最小修改建议：保留方法论，将具体法律引用转为带版本和核验时间的来源记录；避免对历史争议一律套用最新条文。

### 3.5 诉法法有缺失资源与宿主绑定

- `litigation-workflows` 引用包根目录的 `references/source-workflows/`，只拷贝该 skill 目录会断链。
- `claim-chart/SKILL.md:16`、`:266` 引用同目录下 `references/element-templates.md`，实际不存在。
- 冷启动工作流引用 `${PLUGIN_ROOT}/practice-profile.md` 模板，当前包未提供；源文件又大量依赖 `~/.codebuddy/.../practice-profile.md`。
- 多个源工作流包含美国专利、程序、保密特权等规则背景，顶层中国法域提醒不足以自动完成本地化。

最小修改建议：把需要的 references 收入可加载范围，缺失模板补齐或删除引用；用户配置改为项目设置和案件配置；用法域路由选择模板，首期中国民事/劳动争议不自动激活美国程序模板。

### 3.6 费用脚本需要服务化校验

`calculate_lawsuit_fee.py` 可独立运行，普通金额及负数分支已运行验证；`nan`、`inf` 会以退出码 0 输出非有限结果。

最小修改建议：API 层验证有限、非负、范围和精度，金额使用 Decimal；费用规则注明类别、版本、适用范围和估算口径。本次未对所有收费规则进行法律审定。

## 4. CrewAI 角色分配

建议 4 个核心角色，法规与类案检索先由同一研究角色完成；复杂案件需要时再拆为独立专家。

| 角色 | 技能来源 | 输出契约 |
|---|---|---|
| 案件与证据分析员 | litigation-workflows 中 intake、chronology、claim-chart，场景路由技能 | 事实、时间线、证据目录、争议焦点、缺失材料；每项附材料引用 |
| 法律研究员 | legal-search-engine、case-retrieval | 法条与案例原文、版本/效力、适用条件、对抗观点、检索覆盖缺口 |
| 诉讼策略与文书起草员 | china-litigation-toolkit、brief-section-drafter、demand 工作流、legal-output-formatter | 诉前分析、费用估算输入输出、文书草稿、待确认事项 |
| 复核员 | legal-verification-workbench 方法与证据匹配规范 | 引用关联、语义支持/矛盾、效力疑点、补检与修改意见 |

Flow 管理顺序与状态，不额外制造“总经理 Agent”。角色可共享技能，但有不同输出契约与工具权限。默认不进行无边界相互委派。

主流程：上传和解析 → 材料结构化 → 场景路由 → 按需研究 → 分析/起草 → 引用校验与复核 → 有限补检 → 结果或明确缺口。

事实抽取与立场分析分开存储；第三方文档中的指令不能改变角色权限、调用外部发送工具或覆盖系统工作流。

## 5. 用户指定技术栈的落地边界

- Vue：案件工作台、素材预览、事实/证据/法条对照、任务进度、角色输出与最终草稿。
- FastAPI + Worker：上传授权、文件解析、后台长任务、重试、取消、SSE 事件。
- CrewAI：Flow 编排；按任务调用 Agent/Crew；结构化结果使用 Pydantic。业务技能与已安装的 CrewAI 开发辅助技能分开管理。
- MySQL：案件、素材元信息、提取段落、来源版本、引用、运行状态、复核记录。CrewAI 默认持久化不是 MySQL，需显式适配。不得将语义 Memory 作为案件事实唯一存储。
- COS：原件、转图、提取产物及导出文件。私有桶与短期签名；保留原件哈希，临时产物生命周期可配置。数据库保存对象键，不保存过期签名作为永久引用。
- DeepSeek / TokenHub：分别配置供应商、endpoint、model、key 和能力。图片输入按真实模型支持情况发送；PDF 先按页提取文本，扫描页/图表按需转图。provider file_id 与 COS 对象键分开存储。
- 首期不必引入向量数据库：小规模案件先使用受权限限制的材料查询和关键词/分段检索；数据量需要时再明确 embedding 模型和向量存储。
- Node.js 核验工具可先通过受控包装在独立任务目录运行，不必为改用 CrewAI 全部重写；进入服务化前修复上述版本与门禁问题。Vue 使用结构化结果渲染，离线 HTML 是一种导出，不是唯一业务界面。

## 6. 最小实施顺序与验收

1. 建立业务技能副本和资源清单，修复路径、来源策略及中国法域模板；原始包保持不变。
2. 先实现单个案件的完整链路：上传 → 解析 → 材料分析 → 草稿 → 点击引用回原文件/页码。
3. 接入法规/类案来源统一接口、版本存储与复核流程。
4. 接入可选 MCP，分别处理未配置、无结果、失败、来源不完整；缺少真实 endpoint/凭证时，只能声明适配器已实现，不能声明服务已联通。
5. 补齐多案件隔离、费用记录、长任务恢复和导出。

核心验收：关闭全部 MCP 仍可完成上传材料分析；资料不足时说明缺口；相反原文与结论触发复核；不同法规版本不混合；跨案件不得串用素材；扫描件不清晰处标记；模型与 MCP 中断不会生成假成功结果。
